# Icone, miniature, programmi predefiniti e screensaver

Il desktop, Esplora risorse e il selettore Apri/Salva usano un'icona a blocco note per TXT (anche LOG, INI e MD). PNG/JPG/JPEG mostrano una miniatura con cornice, preservando proporzioni e trasparenza. PDF e formati audio/video comuni hanno icone specifiche per estensione. Un clic seleziona, il doppio clic apre il file nell'app associata: il visualizzatore di immagini è l'app predefinita per le foto.

Nel preview PC, trascinare uno o più file da una cartella del computer sul desktop li copia sul Desktop virtuale; se il puntatore è sopra una cartella del desktop o una cartella in Esplora risorse, li copia lì. I file importati mantengono nome ed estensione, compaiono nella destinazione e si aprono con l'app associata al doppio clic. Il trasferimento usa la finestra di avanzamento del sistema.

Le miniature vengono decodificate in C con libpng/libjpeg, usando `SceIo` sulla Vita e lo stesso codice nell'anteprima Linux. Sono grandi al massimo 64×64 pixel. La cache contiene fino a 160 miniature (circa 2,5 MiB di pixel complessivi, oltre all'allineamento delle texture), usa espulsione LRU e invalida una foto quando dimensione/data di modifica cambiano. Le scritture tramite API e il comando Aggiorna invalidano inoltre la cache, anche quando il filesystem mantiene lo stesso timestamp. Non conserva le immagini originali a piena risoluzione. PNG usa righe campionate, anche per Adam7; JPEG sfrutta la riduzione del decoder. File mancanti, non validi o oltre i limiti mostrano un'icona immagine generica. Limiti: sorgenti fino a 64 MB, 16384 pixel per lato e 64 milioni di pixel; JPEG progressivi fino a 16 milioni di pixel per contenere le matrici dei coefficienti.

In **Pannello di controllo → Tipi di file** si sceglie l'estensione, poi **Cambia app** e un'app dell'ambiente. **Ripristina** elimina la scelta personale e torna alla registrazione dell'app; **Aggiungi estensione…** permette di configurare un tipo nuovo. Le preferenze sono in `ux0:/data/desktop-mode/associations.ini`. Le registrazioni delle app tramite API non sovrascrivono una scelta personale. Disinstallando un'app scelta si usa l'associazione disponibile; reinstallandola si riattiva la scelta salvata. `.dmapp`, `.dmsaver` e `.dmlink` restano protette sia nella UI sia nell'API. Le estensioni sono nomi semplici come `.txt`, senza percorsi o estensioni composte. Il programma scelto riceve il percorso del file e deve saper interpretarne il formato: l'associazione non aggiunge un nuovo decoder al programma.

L'anteprima dello screensaver ignorava erroneamente il rilascio del clic che l'aveva aperta: lo stesso input la chiudeva immediatamente. Ora rimane visibile durante il rilascio, poi una nuova azione la chiude. L'anteprima è disponibile anche con l'avvio automatico disabilitato. Il timeout automatico è sospeso durante dialoghi e operazioni su file. I tasti Start/Cerchio che risvegliano lo screensaver non operano anche sulle finestre nascoste.

Verifica: test automatici sulla versione Linux per miniature/colori/alpha, PNG Adam7/palette, JPEG baseline/progressivi e 2000 immagini troncate/modificate sotto AddressSanitizer/UndefinedBehaviorSanitizer, associazioni/persistenza/ripristino/protezioni e anteprima/timeout; compilazione del VPK Vita. Il comportamento su hardware Vita richiede collaudo sulla console. Gli screensaver Windows `.scr` e i binari Linux non sono eseguibili nell'ambiente: per moduli aggiuntivi si usa `.dmsaver` con l'API del progetto.

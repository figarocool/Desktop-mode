# Aggiornamenti da GitHub / GitHub updates

## Italiano

Ogni release GitHub creata con un tag `v...` pubblica il VPK completo, un archivio delle app e un asset `.dmapp` indipendente per ciascuna app integrata. `desktop-mode-update.json` è il manifest versione 1: contiene il tag, il nome dell'asset del core e, per ogni app, il nome dell'asset e il suo SHA-256. `SHA256SUMS` include gli stessi pacchetti. Il manifest è generato da `scripts/create-release-manifest.py` e il workflow è `.github/workflows/release.yml`.

All'avvio Desktop Mode scarica il manifest tramite HTTPS e confronta i checksum delle app integrate con quelli inclusi nella release. Se un'app è cambiata, scarica il relativo `.dmapp` in modo temporaneo, verifica SHA-256 e intestazione WASM, poi lo installa in `ux0:/data/desktop-mode/apps/`. Il caricamento dà precedenza a questi pacchetti rispetto a quelli inclusi nel VPK: l'app aggiornata è quindi attiva già in questa sessione, prima che vengano aperte le sue finestre. Se la connessione o la verifica fallisce, resta installata la versione inclusa nel VPK.

Il controllo e il download usano la build VitaSDK di libcurl collegata a mbedTLS, incorporata staticamente nell'eseguibile: così HTTPS non dipende dal supporto TLS limitato di `SceHttps` nei firmware 3.60–3.65. La verifica del certificato e del nome host resta attiva usando il bundle CA `assets/cacert.pem` incluso nel VPK; i download seguono i redirect HTTPS di GitHub. Durante il download viene mostrata la finestra nativa di avanzamento della Vita con percentuale, quantità ricevuta, nome del pacchetto e destinazione dei file. `ux0:/data/desktop-mode/update.log` registra l'esito delle fasi di rete e installazione.

Se il tag della release è semanticamente più nuovo della versione del core, Desktop Mode scarica `desktop-mode.vpk`, ne verifica SHA-256, controlla titolo e versione nel pacchetto e lo estrae in un'area temporanea. Poi usa `ScePromoterUtility` per installarlo sopra il titolo `DSKMODE01`. Dopo un'installazione riuscita, l'app termina: riaprendola si avvia il core aggiornato. Le build locali marcate `dev` non vengono sostituite da release pubblicate più vecchie. Se la Vita rifiuta l'operazione, il VPK verificato resta in `ux0:/data/desktop-mode/updates/desktop-mode.vpk` e l'errore viene mostrato al successivo avvio; il sistema non ripete all'infinito un tentativo fallito per la stessa release. L'installazione automatica dipende dal firmware modificato e dai permessi HENkaku disponibili; va collaudata sulla console reale, in particolare su firmware 3.60.

## English

Each GitHub release tagged `v...` publishes the complete VPK, an app archive, and one standalone `.dmapp` asset for every bundled app. `desktop-mode-update.json` is schema version 1: it records the tag, the core asset name, and each app asset name and SHA-256 digest. `SHA256SUMS` covers those packages too. The manifest is generated by `scripts/create-release-manifest.py`; the workflow is `.github/workflows/release.yml`.

At startup, Desktop Mode fetches the manifest over HTTPS and compares the installed built-in app packages with the release checksums. For each changed app, it downloads a temporary `.dmapp`, verifies SHA-256 and its WASM package header, then installs it under `ux0:/data/desktop-mode/apps/`. The loader gives these packages priority over the copies embedded in the VPK, so the updated app is active in the current session before its window is opened. If the connection or verification fails, the VPK-bundled app remains available.

The updater uses the VitaSDK libcurl build linked to mbedTLS, statically included in the executable, so HTTPS does not depend on the limited TLS support in `SceHttps` on firmware 3.60–3.65. Certificate and hostname verification remain enabled with the `assets/cacert.pem` bundle included in the VPK; GitHub HTTPS redirects are followed. During downloads, the Vita's native progress dialog shows the percentage, bytes received, package name, and destination paths. `ux0:/data/desktop-mode/update.log` records network and installation stages.

If the release tag is semantically newer than the embedded core version, Desktop Mode downloads `desktop-mode.vpk`, verifies its SHA-256, validates the package title and version, and extracts it to a temporary area. It then calls the Vita's `ScePromoterUtility` to install it over title `DSKMODE01`. After success, the app exits; opening it again starts the updated core. Local builds marked `dev` are not replaced by older published releases. If Vita rejects the operation, the verified VPK remains at `ux0:/data/desktop-mode/updates/desktop-mode.vpk` and the error is shown on the next launch. The same release is not retried forever. Automatic installation depends on the modified firmware and available HENkaku permissions and must be tested on real hardware, especially firmware 3.60.

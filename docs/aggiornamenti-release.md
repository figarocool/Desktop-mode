# Aggiornamenti da GitHub / GitHub updates

## Italiano

Ogni release GitHub creata con un tag `v...` pubblica il VPK completo, un archivio delle app e un asset `.dmapp` indipendente per ciascuna app integrata. `desktop-mode-update.json` è il manifest versione 1: contiene il tag, il nome dell'asset del core e, per ogni app, il nome dell'asset e il suo SHA-256. `SHA256SUMS` include gli stessi pacchetti. Il manifest è generato da `scripts/create-release-manifest.py` e il workflow è `.github/workflows/release.yml`.

All'avvio Desktop Mode scarica il manifest tramite HTTPS e confronta i checksum delle app integrate con quelli inclusi nella release. Se un'app è cambiata, scarica il relativo `.dmapp` in modo temporaneo, verifica SHA-256 e intestazione WASM, poi lo installa in `ux0:/data/desktop-mode/apps/`. Il caricamento dà precedenza a questi pacchetti rispetto a quelli inclusi nel VPK: l'app aggiornata è quindi attiva già in questa sessione, prima che vengano aperte le sue finestre. Se la connessione o la verifica fallisce, resta installata la versione inclusa nel VPK.

Se la versione del core inclusa nel VPK è diversa dal tag della release, il sistema scarica `desktop-mode.vpk`, ne verifica SHA-256 e lo salva in `ux0:/data/desktop-mode/updates/desktop-mode.vpk`. Desktop Mode non installa da solo un VPK e non sostituisce il processo in esecuzione: l'utente deve installare il file tramite il flusso homebrew della console e riavviare.

## English

Each GitHub release tagged `v...` publishes the complete VPK, an app archive, and one standalone `.dmapp` asset for every bundled app. `desktop-mode-update.json` is schema version 1: it records the tag, the core asset name, and each app asset name and SHA-256 digest. `SHA256SUMS` covers those packages too. The manifest is generated by `scripts/create-release-manifest.py`; the workflow is `.github/workflows/release.yml`.

At startup, Desktop Mode fetches the manifest over HTTPS and compares the installed built-in app packages with the release checksums. For each changed app, it downloads a temporary `.dmapp`, verifies SHA-256 and its WASM package header, then installs it under `ux0:/data/desktop-mode/apps/`. The loader gives these packages priority over the copies embedded in the VPK, so the updated app is active in the current session before its window is opened. If the connection or verification fails, the VPK-bundled app remains available.

If the VPK's embedded core version differs from the release tag, the system downloads `desktop-mode.vpk`, verifies its SHA-256, and stages it at `ux0:/data/desktop-mode/updates/desktop-mode.vpk`. Desktop Mode does not install a VPK itself or replace its running process; the user must install the staged package through the console's homebrew installation flow and restart.

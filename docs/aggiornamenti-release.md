# Aggiornamenti da GitHub / GitHub updates

## Italiano

Ogni release GitHub creata con un tag `v...` pubblica il VPK completo, un archivio delle app e un asset `.dmapp` indipendente per ciascuna app integrata. `desktop-mode-update.json` è il manifest versione 1: contiene il tag, il nome dell'asset del core e, per ogni app, il nome dell'asset e il suo SHA-256. `SHA256SUMS` include gli stessi pacchetti. Il manifest è generato da `scripts/create-release-manifest.py` e il workflow è `.github/workflows/release.yml`.

Questi asset rendono possibile scaricare e verificare gli aggiornamenti separati. Il client di aggiornamento automatico non è ancora implementato nel desktop: al momento non esegue il controllo periodico/avvio, non scarica il manifest e non installa automaticamente le app. Per applicare un aggiornamento `.dmapp` in sicurezza occorre integrarlo nel gestore app e attivarlo quando la relativa finestra/modulo non è in uso, quindi ricaricare il modulo. Il VPK del core può essere scaricato e verificato in una cartella di staging; sostituire l'applicazione che sta eseguendo il codice richiede però il flusso d'installazione della console e un riavvio. Questo workflow non tenta installazioni kernel o sostituzioni del VPK in esecuzione.

Il client futuro può ottenere l'ultima release tramite l'API GitHub Releases (`/repos/{owner}/{repo}/releases/latest`), trovare l'asset per nome, scaricarlo su `ux0:/data/desktop-mode/updates/` e confrontare SHA-256 prima di passarlo al gestore app. Deve mantenere la versione installata e fare il cambio in modo atomico, conservando la versione precedente per il rollback. Per il core deve mostrare che il VPK è pronto e chiedere l'installazione tramite il flusso supportato dalla console.

## English

Each GitHub release tagged `v...` publishes the complete VPK, an app archive, and one standalone `.dmapp` asset for every bundled app. `desktop-mode-update.json` is schema version 1: it records the tag, the core asset name, and each app asset name and SHA-256 digest. `SHA256SUMS` covers those packages too. The manifest is generated by `scripts/create-release-manifest.py`; the workflow is `.github/workflows/release.yml`.

These assets provide the download and integrity contract for separate updates. The automatic update client is not implemented in the desktop yet: it does not check releases on launch or download and install the manifest's assets. Safe `.dmapp` installation must be integrated with the app manager and applied when the corresponding window/module is no longer active, followed by a module reload. The core VPK can be downloaded and verified in a staging directory, but replacing the application that is currently executing requires the console's installation flow and a restart. This workflow does not attempt kernel installation or replacement of a running VPK.

A future client can query GitHub Releases (`/repos/{owner}/{repo}/releases/latest`), find assets by name, download to `ux0:/data/desktop-mode/updates/`, and verify SHA-256 before handing an app package to the app manager. It should record installed versions, swap packages atomically, and retain the previous version for rollback. For a core update, it should report that the VPK is ready and request installation through the console-supported flow.
